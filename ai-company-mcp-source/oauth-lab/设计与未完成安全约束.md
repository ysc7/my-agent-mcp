# OAuth 实验设计（未实现，不可部署）

本目录仅含设计，不提供 OAuth 服务、可运行原型、配置或凭据。身份服务尚未选定；GitHub 只是可选示例，默认不启用任何登录方式。尚未进行本地功能或安全测试，不能声称可用于 Muse 或生产环境。没有访问任何用户账号或执行部署。

## 范围与边界

目标是在独立 Worker 中使用 Cloudflare 官方 `@cloudflare/workers-oauth-provider` 提供 MCP 授权发现、授权码、token 和资源保护；上游身份适配器可选，默认关闭。任何缺失、无效或不一致的配置必须拒绝授权和访问，而不是回退至匿名或固定默认身份。依赖必须锁定版本并审查该版本的实际 API 和安全行为，不应假定主分支文档适用于任意已发布版本。

GitHub 适配器仅在管理员显式选择时启用：配置唯一的 GitHub 数字用户 ID（以规范十进制字符串保存，避免 JavaScript 数值精度损失），从 GitHub 的已认证用户 API 获取并严格验证 ID，与配置精确比较；用户名、邮箱或显示名不作为身份依据。服务端持有 GitHub client secret，上游 access token 不交给 MCP 客户端，不记录日志，使用后丢弃。不存在允许所有 GitHub 用户的默认配置。具体 GitHub OAuth App 注册、支持的 PKCE 行为、错误处理和账号变更操作都必须按选定 API 的最新官方文档验证，不能假定 GitHub OAuth 支持某个未验证的 PKCE 参数。

必须预配置从**可信的、预先批准的客户端标识**到唯一 agent 名称的固定映射；服务端确定 agent，绝不接受请求参数、客户端展示名称或用户自由输入作为 agent 身份。仅凭公开 client_id 不能证明客户端身份；动态注册得到的 client_id 或 CIMD 元数据也不能被当作已授权 agent 的凭据。需先确定 Muse 的客户端注册和认证能力，再设计能证明已批准客户端持有凭据的绑定；否则禁止发令牌，不能声称已经实现固定 agent 身份。MCP token 的主体、客户端绑定、范围及 resource/audience 必须与该映射一致；管理身份与 agent 严格隔离。

## 拟定授权流程与未完成约束

1. 对授权请求由官方库解析和验证 client、精确 redirect URI、scope、resource、response type。除明确定义的 scope 外拒绝；公共客户端要求 S256 PKCE，且必须验证所选库版本对所有拟支持客户端的执行情况。仅允许受控客户端，禁止自动信任任意动态注册或客户端元数据。
2. 对上游登录创建高熵、短期的 state，绑定浏览器安全 cookie、原始授权请求、客户端与精确回调；不能用可预测值或仅以可由攻击者自选的 cookie 作为绑定。callback 严格验证 state、cookie、期限及来源，拒绝缺失、篡改、重放与跨浏览器混淆。需要可原子消费的事务存储及并发测试，不能把 KV 的最终一致性当作全局单次使用保障。若上游支持并已验证 PKCE，再使用独立 verifier、S256 和安全存储；下游 PKCE 与上游 PKCE 不共用 verifier。
3. 用户身份验证成功后显示明确 consent：展示经过 HTML 转义的真实客户端标识、目标 agent、请求资源及最小权限，提供允许和拒绝；表单使用与浏览器会话绑定的一次性 CSRF 防护，严格 Origin 检查并限制重放。未经用户确认不得授权；不能通过 GET 或自动提交完成批准。配置严格 CSP、无缓存、无第三方资源及防 referrer 泄漏策略。
4. 官方库完成授权并验证 token。对资源请求校验 issuer、有效期、audience/resource、scope、客户端和当前授权映射；身份撤销或映射变更应阻止后续访问。明确授权码、刷新 token 的并发重放和撤销传播窗口，无法满足安全要求时拒绝使用该架构，而非宣称即时全局撤销。限制日志、错误消息、回调 URL 的敏感信息，并设置速率限制。
5. 事务、密钥、令牌与安全 cookie 的生命周期、旋转和失效策略尚未实现；真实生产环境还需 HTTPS、可信 host、严格回调地址及部署密钥管理。

## 与现有消息 Worker 的集成障碍

现有 `src/index.ts` 的 MCP 身份通过 `AGENT_TOKENS` 中的 Bearer 静态密钥决定，管理端使用独立 `ADMIN_TOKEN`；它不会接受 OAuth access token。直接将 OAuth token 转发给它不能登录；向客户端暴露静态 agent 密钥也不可接受。若保持现有源码不变，可研究单独可信网关：验证 OAuth token 后在服务端从受保护配置选择对应的静态 agent 密钥并调用后端；必须先确保后端不能绕过网关被外部访问、密钥不可泄露、身份映射和撤销一致、管理员接口不能经网关暴露。服务绑定/网络隔离、网关转发请求与响应的细节和对完整 MCP 协议的兼容性均未实现或验证。否则需未来经用户同意改造后端，而本任务没有改动它。

## 落地前必须完成的本地验证

- 使用选定版本的官方库、隔离的模拟上游和 Workers 本地运行环境，测试完整发现 → 授权 → consent → 回调 → token → MCP 流程；测试 Muse 的实际能力，不以假客户端代替兼容性验收。
- 拒绝未配置身份服务、错误 GitHub 数字 ID、失效或错误配置、其他客户端和任意 agent 注入；覆盖客户端冒充和直接访问后端绕过网关。
- 覆盖错误或缺失 PKCE、错误 redirect URI/resource/scope、伪造和过期 state、跨浏览器回调、拒绝 consent、CSRF、恶意 client 名称/XSS、开放重定向和敏感信息泄露。
- 并发重放授权码、state、consent 和 refresh token；在真实 Cloudflare 一致性模型下验证，单进程 mock 通过不足以证明跨区域原子性。验证撤销、过期、配置变更、故障关闭和时钟偏差。
- 隔离管理端、最小权限、私信读取/发送的真实 agent 身份、连接断开与错误处理；审查依赖及进行独立安全审计。
